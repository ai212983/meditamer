|Code size policy: The `part-NN` anti-sharding rule above applies to Rust as well as Markdown. **A split that does not create a module boundary is not a split.** If the pieces cannot each be a `mod` with its own imports and privacy, the file was not too long — leave it. In particular `include!` is for build-script output only: `include!(concat!(env!("OUT_DIR"), ...))`. Pasting a hand-written source file into a parent yields no module boundary, no privacy, no independent `use` list, and degrades rust-analyzer across the seam. `scripts/ci/check_include_usage.sh` inventories all first-party Rust and runs with `INCLUDE_USAGE_ENFORCE=1` in hooks and the quality lane, so the practice cannot return.
