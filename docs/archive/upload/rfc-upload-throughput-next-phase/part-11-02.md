## 11.62 2026-03-05 Scan-Entry Promiscuous RX Sweep Diagnostics

Objective:

- classify whether scan-zero recurrence is a scan-engine-only issue or a broader
  radio RX-ingress blackout by sampling promiscuous RX packet counts immediately
  at scan entry.

Implementation:

- files:
  - `src/firmware/storage/upload/wifi/connect/promisc_diag.rs`
    - add compile-time knob `MEDITAMER_WIFI_SCAN_ENTRY_PROMISC_DIAG`
      (`0` default).
    - add per-window dwell knob
      `MEDITAMER_WIFI_SCAN_ENTRY_PROMISC_DIAG_DWELL_MS` (`120 ms` default).
    - register promiscuous callback and sweep channels `[8, 1, 6, 11]` at scan
      entry, logging per-channel packet counts (`mgmt/ctrl/data/misc`).
  - `src/firmware/storage/upload/wifi/connect/mod.rs`
    - register module.
  - `src/firmware/storage/upload/wifi/connect/prepare/prepare_scan.rs`
    - run promiscuous sweep diagnostic at scan entry (diag-only).

Runs (bounded, `rounds=1`, listener off):

- `logs/wifi_discovery_debug_step65_promiscsweep_1r_20260305_124610.log`
- `logs/wifi_discovery_debug_step65_promiscsweep_sanity_1r_20260305_125455.log`

Observed:

- both runs remained discovery-empty:
  - `ready=false`, `scan_zero=44`, `scan_nonzero=0`.
- promiscuous sweep succeeded operationally (`set_channel_rc=0`,
  `enable_rc=0`, `disable_rc=0`), but all windows were zero:
  - `channel=8 total=0`
  - `channel=1 total=0`
  - `channel=6 total=0`
  - `channel=11 total=0`
  - aggregate `total=0 mgmt=0 ctrl=0 data=0 misc=0`.
- in the same cycles, staged scans also returned all-zero
  (`scan_done status=0 count=0`, `result_count=0`).

Interpretation:

- this narrows the blocker to radio RX-ingress blackout behavior, not just scan
  result marshaling/wrapper logic.
- next root-cause focus should target deeper RX-path/radio-state recovery
  mechanisms compatible with current `esp-radio` support.

## 11.63 2026-03-05 `esp_wifi_restore()` Recovery Branch Rejected

Objective:

- test a deeper post-stop recovery primitive by calling `esp_wifi_restore()`
  after successful `stop` in zero-discovery restart paths.

Implementation attempt:

- file touched during attempt:
  - `src/firmware/storage/upload/wifi/connect/recovery.rs`
  - temporary knob branch `MEDITAMER_WIFI_RESTORE_AFTER_STOP`.
- branch was immediately reverted after live failure.

Validation run:

- `logs/wifi_discovery_debug_step65_restoreafterstop_promiscsweep_1r_20260305_125124.log`

Observed:

- runtime panic on first recovery cycle:
  - `panicked ... esp-radio-0.17.0/src/common_adapter.rs:318:5`
  - message: `not yet implemented: misc_nvs_restore`.

Interpretation:

- `esp_wifi_restore()` is currently unsupported in this stack path and cannot
  be used as a recovery primitive.
- mark as rejected to avoid repeated dead-end retries.

## 11.64 2026-03-05 Force-Wakeup Scan Guard A/B Rejected

Objective:

- test whether discovery-empty recurrence is caused by modem sleep/RF wake
  state by holding a Wi-Fi force-wakeup reference during scan rounds.

Implementation attempt:

- file:
  - `src/firmware/storage/upload/wifi/connect/prepare/prepare_scan.rs`
- temporary scan guard branch using:
  - `esp_wifi_force_wakeup_acquire()`
  - `esp_wifi_force_wakeup_release()`.
- branch reverted after live result.

Validation run:

- `logs/wifi_discovery_debug_step65_forcewake_promiscsweep_1r_20260305_131302.log`

Observed:

- discovery remained all-zero (`scan_nonzero=0`).
- promiscuous sweep remained all-zero across channels (`8/1/6/11`).
- release path emitted repeated non-fatal errors:
  - `scan_force_wakeup release_rc=12290`.

Interpretation:

- force-wakeup scan guard did not recover discoverability and introduced extra
  control-path churn.
- keep this branch rejected.
