  - `scan_zero_discovery_driver_restart zero_discovery_hard_guard software_reset=true ...`

## 11.71 2026-03-05 Host Expected-Reboot Recovery Hook Added for Discovery Workflow

Objective:

- prevent intentional zero-discovery software resets from being hard-classed as
  runtime panic in discovery workflow.

Implementation:

- host files:
  - `tools/hostctl/src/workflows_wifi_common/mod.rs`
  - `tools/hostctl/src/workflows_wifi_discovery/probe.rs`
  - `tools/hostctl/src/workflows_wifi_discovery/runtime.rs`
- behavior:
  - if log stream arms expected reset via firmware marker
    (`software_reset=true`) and next panic-class line is
    `UnexpectedReboot`, workflow suppresses that panic once per round,
    re-applies `NETCFG SET`, and retries `NET START`.

Run:

- `logs/wifi_discovery_debug_step65_softreset_hardguard_on_hostrecover_1r_20260305_140238.log`
- host summary:
  - `ready=true`, `scan_zero=0`, `scan_nonzero=1`, `ssid_seen=2`.

Validation gap:

- additional short 3-round runs passed with ready-state but no scan telemetry
  evidence (`scan_zero=0`, `scan_nonzero=0`, `ssid_seen=0`) in:
  - `logs/wifi_discovery_debug_step65_softreset_hardguard_on_hostrecover_3r_20260305_140337.log`
  - `logs/wifi_discovery_debug_step65_softreset_hardguard_on_hostrecover_3r_recover_20260305_140349.log`
- indicates follow-up should enforce scan-evidence collection when validating
  this branch.
